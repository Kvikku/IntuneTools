InToolz 2.0 concepts

Three structural directions for 2.0

These are static, clickable sketches — no real data or logic. Each one rethinks how InToolz is organized at the structural level, not just the color palette. Open any card below.

Direction 1 — Verb-first · ⭐ selected, now fully built out

Command Center

Drops the left nav entirely. A dashboard of live stats (unassigned items, stale devices, duplicates) plus a search-driven command palette (Ctrl+K) replace page-browsing — you type what you want to do instead of hunting for the right nav item. Now mocked up end-to-end: Assignment, Manage Assignments, Cleanup, Renaming, Import, JSON, Audit Log, and Settings all follow this shell.

Tradeoff: new users don't yet know the verbs to search for — needs a visible fallback.
Direction 2 — Object-first

Workbench

One unified object browser across all content types, filtered by a left rail instead of by operation. Select items first, then a contextual action bar offers whatever bulk actions apply — assign, rename, export, delete — same mental model as File Explorer.

Tradeoff: cross-tenant Import doesn't fit a single-tenant grid as cleanly — needs a dedicated mode.
Direction 3 — Job-first

Mission Control

Every bulk action becomes a configurable, queueable job. A persistent job queue panel (like a download manager) tracks running/queued/completed jobs with per-item success/fail, so several operations can run side by side instead of blocking one page.

Tradeoff: biggest rewrite — orchestrators need true async queueing, not page-blocking calls.
Today, for reference: a NavigationView sidebar with one page per verb (Home, Assignment, Manage Assignments, Import, Cleanup, Renaming, JSON, Audit Log, Settings), each following the same header → toolbar cards → grid + side-panel layout defined in docs/UI_STANDARD.md. All three directions above assume that per-page layout is replaced, not incrementally restyled.
